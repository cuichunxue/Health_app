# Today One 事業化戦略

対象: Today One プロトタイプ（ユーザー向け3画面 + 非表示の Learning Console）
作成日: 2026-08-21

## 要旨

- ユーザーに見える3画面（今日 / 変える / 進歩）の裏に、アバターをタップすると開く非表示の **Learning Console** があり、Adaptive（状態適応）実行率 74% vs Fixed（固定メニュー）実行率 61%（+13pt リフト）、未実行理由の分類、学習済みの個人ルール、Health Value Gate の閾値（70/100）まで、事業判断に使える資産がすでに埋め込まれている。
- 最大の差別化要因は「簡単さに合わせて健康価値の基準は下げない」という明文化されたルール。ゲーミフィケーション型の継続アプリとの明確な違いであり、B2B2C（保険者・企業）調達の説明責任にそのまま応える。
- 主軸は B2B2C（健保組合の特定保健指導、企業の健康経営）。B2C は無料入口としてデータと認知を稼ぐ役割に限定する。
- 投資順序は Learning Console 自身が定義した H1 (Fit) → H2 (Learning) → H3 (Persistence) のゲートに従う。H2 が成立するまで ML／「AI搭載」訴求への投資と広告表現を控える。

## 1. これは何が作られているか

ユーザー向けの「今日画面」は、体力・時間・場所という3つの状態から選ばれた1つの行動だけを提示する単一行動提示型 UI。「なぜこれ？」で提示理由を開示し、「今日は難しい」から6つの障壁（時間・疲労・環境・強度・意欲・家庭事情）を選ばせ、健康価値を落とさない範囲で軽い代替案に切り替える。

本質的な資産は非表示の Learning Console にある。パイプラインは以下の通り:

```
Action Library → Health Value Gate → Context → Execution Fit → Today One
→ 実行/未実行 → Reason Classifier → Rule Update
```

これは UI モックではなく、行動データが毎日ルールを更新する閉ループの意思決定エンジンのプロトタイプ。売るべき商品は UI ではなく、このエンジンだと理解した方が戦略が立てやすい。

## 2. 最大の事業資産は「下げない」という約束

Learning Console の「安全・意思決定」欄:

> Health Value Threshold：70/100　／　Gate未達：候補から除外　／　**簡単さに合わせた基準変更：禁止**

多くの継続系ヘルスケアアプリは離脱防止のために「達成しやすさ」を優先し、行動の中身が空洞化しがちである。TodayOne は負荷を個人に合わせて下げても、「健康価値として意味があるか」の下限は動かさないという設計思想をコードレベルで明文化している。これは対外的な信頼訴求と B2B 調達要件の両方に転用できる。

## 3. 誰に売るか

| チャネル | 買い手 | 強み | 時間軸 |
|---|---|---|---|
| **B2B2C（本命）** | 健保組合・企業人事（健康経営） | 予算あり／Gate資産と相性◎／解約が起きにくい | 中期（パイロット3〜6ヶ月） |
| B2C フリーミアム | 個人ユーザー | 認知の入口・データ収集源 | 短期開始可、収益化は遅い |
| エンジン提供（将来） | 他アプリ・ウェアラブル・製薬アドヒアランス | Gate＋Fitエンジンを部品として売る | 長期（H2/H3実証後） |

推奨: B2B2C を主軸、B2C は無料入口に限定。エンジン提供は H2/H3 成立後のオプションとして温存する。

## 4. 価格設計

- **B2B2C**: 対象者あたり月額（PMPM）を基本形にしつつ、初回パイロットは特定保健指導の実施率／完了率改善を条件にした成果連動フィーを併用。74% vs 61% のリフト実績を交渉材料にする。
- **B2C**: 基本行動（今日画面）は無料。個人ルールの詳細解説・週次インサイト・複数ドメイン拡張（睡眠・食事など）を有料ティアに。
- 健康価値の下限（Gate）は機能制限の対象から明確に除外し、「安い方でも安全性は妥協しない」という約束自体を営業資料に載せる。

## 5. 立ち上げの順番

1〜2社の健保組合、または健康経営に本気の中堅企業の人事部を設計パートナーとして口説き、既存のリフト実績データをそのまま提案資料の1枚目に使う。3〜6ヶ月の有料パイロットで完了率・継続率の改善を測定し、実績を次の見込み先への営業証拠として横展開する。人間ドック運営会社や既存の福利厚生プラットフォームなど、健保組合と取引のあるチャネルパートナー経由の紹介も並行して探る。

## 6. 投資の順番は H1 → H2 → H3 のゲートに従う

- **H1 Fit（検証中）**: 状態適応で実行率が上がるか。すでに +13pt のリフトが出ており、営業に使ってよい段階に近い。
- **H2 Learning（待機）**: 使うほどルールが賢くなるか。ここが成立するまで ML への投資は禁止、というルールが Console に明記されている。
- **H3 Persistence（待機）**: 効果が続くか。解約率と LTV を決める。

**推奨**: 「AI搭載」を今のマーケティングの前面に出さない。今売れる価値はルールベースの Fit エンジンによる実測リフトであり、H2 が成立する前に AI を訴求すると証明していない効能を語ることになり、規制リスクも増える。

## 7. リスクと規制

- **薬機法**: 「実行率」「継続率」は指標として使えるが、疾病の診断・治療・予防効果を示唆する表現は避け、生活習慣支援としての訴求に留める。
- **個人情報保護法・要配慮個人情報**: 体力・疲労・行動ログは要配慮個人情報に近い扱いが必要。企業経由導入では、個人の実行データを雇用主に渡さず集計値のみ提供する壁を製品設計に組み込む。
- **実装上の穴**: 現状のコードは、アバターをタップするだけで誰でも Learning Console（内部の実行率比較・実験仮説・個人ルール・Gate閾値）を開ける状態になっている。本番投入前に認証済み管理者専用画面として分離するか、開発フラグの裏に隠す必要がある。ここが漏れると競合や導入先に内部の意思決定ロジックがそのまま見えてしまう。

## 8. 次の30/60/90日

- **〜30日**: Learning Console を内部専用に隔離。既存リフト実績を B2B2C 向け資料1枚に整理し、設計パートナー候補を2〜3社リストアップ。
- **〜60日**: 1社とパイロット契約。PMPM＋成果連動の料金モデルを実地テストし、雇用主向け集計と個人向け詳細の権限分離を実装。
- **〜90日**: パイロットの完了率・継続率データを回収。H2 の検証を開始し、次の2社への営業に実績を転用。
